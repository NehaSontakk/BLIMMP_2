# `ATB_KO_Frequencies/`

Splits the global KO matrix by taxonomy, computes per-lineage KO counts,
co-occurrence matrices, and frequencies, then refills KEGG module graph
topology with lineage-specific co-occurrence weights.

---

## Pipeline overview

| Order | Script | What it does | Input | Output |
|-------|--------|-------------|-------|--------|
| 1 | `lineage_specific_ko_matrix.py` | Splits global matrix into one matrix per lineage | `ko_matrix.tsv`, `sampleids_*_priors.csv` | `KO_Matrices/ko_matrix_sampleids_<lineage>.csv` |
| 2 | `make_lineage_command_lists.sh` | Generates one command per lineage for job arrays | `KO_Matrices/ko_matrix_*.csv` | `ko_count_lineage_commands.txt`, `ko_intersection_lineage_commands.txt` |
| 3a | `run_counts_parallel.sbatch` | Runs `ko_counts_one.py` for all lineages in parallel | `ko_count_lineage_commands.txt` | `KO_Counts_Lineage_Specific/ko_counts_*.tsv` |
| 3b | `run_intersections_parallel.sbatch` | Runs `ko_intersection_one.py` for all lineages in parallel | `ko_intersection_lineage_commands.txt` | `KO_Intersections_Lineage_Specific/ko_intersection_*.tsv` |
| 3c | `run_domain.sh` | Runs `ko_intersection_one.py` for domain level only (large memory) | `ko_matrix_sampleids_domain_level_priors.csv` | `ko_intersection_ko_matrix_sampleids_domain_level_priors.tsv` |
| 4 | `KO_frequency.py` | Divides per-lineage KO counts by sample size → frequency | `KO_Counts_Lineage_Specific/`, `Lineage_Specific_SampleNames/` | `KO_Frequencies_Lineage_Specific/ko_freq_*.tsv` |
| 5 | `create_neighbors_all_lineages_update_Dec9.py` | Refills KEGG neighbor JSONs with lineage-specific co-occurrence weights | `KO_Intersections_Lineage_Specific/`, `KO_Counts_Lineage_Specific/`, topology JSONs | `ONE_HOP_NEIGHBOR_DATA/`, `TWO_HOP_NEIGHBOR_DATA/`, `MODULE_ALL_NEIGHBOR_DATA/` |

Steps 3a, 3b, 3c run concurrently. Step 4 needs 3a. Step 5 needs 3b and 3c.

**Not part of active pipeline:**
`build_neighbor_conditionals.py` and `merge_conditionals.py` are superseded by
step 5 — keep for reference only.

## Nuances

**`lineage_specific_ko_matrix.py`**
- Streams `ko_matrix.tsv` once and writes all lineage files simultaneously —
  do not interrupt mid-run or output files will be incomplete.
- Sample IDs in `sampleids_*.csv` not found in the global matrix are silently
  dropped. Check the summary printout (`requested N -> wrote M columns`) to
  catch missing samples.
- Outputs are tab-delimited but have `.csv` extension — this is a known
  inconsistency, works because downstream scripts all use `sep="\t"`.

**`make_lineage_command_lists.sh`**
- Re-running is safe — truncates command files before writing.
- Must run after step 1 or the glob finds nothing and the script exits.

**`ko_counts_one.py` / `ko_intersection_one.py`**
- Both handle 0-sample lineages gracefully (`[SKIP DATA]`) — these files should
  not exist under normal operation but won't crash the job array if they do.
- `ko_intersection_one.py` does not re-binarise before multiplying. Safe as long
  as the input matrix is strictly binary.

**`run_counts_parallel.sbatch` / `run_intersections_parallel.sbatch`**
- Threading env vars (`OMP_NUM_THREADS=1` etc.) are required — without them
  numpy/scipy spawns sub-threads per job and oversubscribes the node.
- If intersection jobs hit the 32 GB memory limit, reduce `-j` to run fewer
  lineages simultaneously rather than increasing memory.
- Conda init path is hardcoded to `/home/u13/nsontakke/miniconda3/...` — update
  if running under a different account.

**`run_domain.sh`**
- Submit with `sbatch run_domain.sh`, not executed directly.
- Domain level is run separately because it contains all genomes and needs 64 GB.
- `/usr/bin/time -v` reports peak memory — check this to tune future requests.

**`KO_frequency.py`**
- `n_samples` is line-counted from the sample CSV, not the matrix column count.
  If these disagree (genome dropped post-matrix), frequencies will be silently
  wrong.
- File pairing is by string manipulation — a name mismatch silently skips that
  lineage with `[WARN]` rather than raising an error.

**`create_neighbors_all_lineages_update_Dec9.py`**
- Only reads intersection values needed by the topology structures (sparse load)
  — do not remove the `collect_needed_pairs` step or memory use will spike.
- KO IDs with adjudication suffixes (e.g. `K00001_1`) are normalized to
  `K#####` via `base_ko()` — this must stay consistent with however the
  intersection files were generated.
- Missing counts files are treated as all-zero (warning only) — a `_count: 0`
  entry will cause division-by-zero if BLIMMP computes conditionals internally.
  Ensure counts and intersection files are always paired before running.
- Currently reads from `copied_from_cgoubert/` while all other scripts read
  from `/xdisk/cgoubert/nsontakke/` — consolidate before next full run.
- Debug prints for K00150/K15634 and K11389/K15634 run for every lineage —
  remove before paper submission.
